# 护符系统 —— HK 装配界面逻辑梳理 + 素材清单

> 来源：`reference/HK/Assembly-CSharp/Assembly-CSharp` 反编译源码 + HK 游戏资源。
> 目标：在 AIC 模组里为小骑士实现护符系统，装配界面参照 HK 原版逻辑。

## 一、HK 原版护符装配界面逻辑

### 界面结构
HK 的护符装配界面是一个名为 **“Charms Pane”** 的 UI 面板（Tag: `Charms Pane`），
交互状态机是挂在它上面的 PlayMaker FSM **“UI Charms”**（核心交互逻辑在 FSM 里，
C# 侧只有钩子与数据）。界面分两块：

1. **上部：护符库存（网格）**
   - 每个格子 = `InvCharmBackboard`（背景板）+ 一个护符图标。
   - 背景板有 `blankSprite`（未获得/空格）与 `activeSprite`（已获得的格子）。
   - 新获得的护符格子上显示 `newOrb`（小圆点，选中后 `SimpleFadeOut` 淡出）。
   - 每个格子绑 `charmNum` / `charmNumString` / `gotCharmString` / `newCharmString`
     （对应 PlayerData 的 `gotCharm_XX` / `newCharm_XX` 布尔）。
2. **下部：装备栏（横向一排）**
   - `BuildEquippedCharms` 按 `PlayerData.equippedCharms`（List&lt;int&gt;）顺序实例化护符图标：
     `START_X=-7.28, START_Y=-3.86, CHARM_SCALE=1.15, 间距 1.76`（>10 个时收窄）。
   - 末尾显示 `nextDot`（下一个空槽提示点）。
   - `UpdateNotches()`（槽位点数刷新，原版在 FSM 里做）。

### 护符图标（CharmDisplay / CharmIconList）
- `CharmDisplay` 挂在每个护符图标上：按 `id` 从 `CharmIconList.spriteList[id]` 取图；
  特殊 id 走变体：
  - 23/24/25 脆弱护符碎裂 → `brokenGlassHP/Geo/Attack`
  - 36 虚空之心 → `whiteCharm` / `blackCharm`（按 `royalCharmState`）
  - 40 格林之子 → `grimmchildLevel1..4` / `nymmCharm`
- 装配成功时：FSM 写 “Newly Equipped Name”，`Check()` 检测到后播放
  `charmPlaceEffect` 并点亮 `flashSpriteRenderer`（闪光层）。
- 超载（`overcharmed`）时图标抖动。

### 交互流程（FSM “UI Charms” + C# 钩子）
1. 选中库存格子 → `SelectCharmBackboard` → 清 `newCharm`（新护符圆点淡出）。
2. 选择护符 → 检查槽位 → 装备/卸下 → 更新 `equippedCharms`、`charmSlotsFilled`。
3. 成功 → 播放装配特效 + 闪光；失败（槽位不足）→ 失败反馈；超载 → 特殊反馈。
4. 槽位点数：`charmSlots`（上限 11）/ `charmSlotsFilled` + 已装备护符 cost 总和。

### 关键数据（PlayerData）
- `gotCharm_1..39`：是否拥有（`gotCharm_36` 不存在，36 用 `royalCharmState`）。
- `equippedCharms`：装备中的护符 id 列表（顺序 = 装备栏顺序）。
- `charmSlots`（上限 11）/ `charmSlotsFilled` / `overcharmed`。
- `charmCost_1..40`：各护符槽位消耗（见下表）。
- `brokenCharm_23/24/25`、`royalCharmState`。

### 3. 原版界面结构（level1 场景，护符菜单）

- **库存**：`Backboards` 容器 → `BB 1..40`（`charm_backboard`）+ 护符图标（Inv_0010..0013 图集块）。
- **装备栏**：`Equipped Charms` 容器 → 护符图标排 + `Sprite Next`（`charm_cost`）。
- **槽位指示**：`Notches` + `Text Notches`（TMPro，文案键 `CHARM_TXT_NOTCHES`=“凹槽”）
  与 `Charm Cost 1..12`（12 个 FSM 驱动对象）；费用圆点 `Cost 1..6`（lit 默认，FSM 切 unlit/染色）
  与 `Over 1..6`（超载态，`notchOverColor` 染红）。
- **超载**：`OC Backboard`（overcharm_backboard）+ 3 层裂纹
  （`crack_big`=0004、`UI_overcharm_crack_effects_0005`、`0006`）+ `Overcharm_Break` 碎裂粒子 + `Text Overcharmed`。

### 4. 相关本地化键（ZH_UI）

`CHARM_TXT_NOTCHES`=凹槽、`CHARM_TXT_COST`=花费、`CHARM_TXT_NOTCHCOST`=需要凹槽、
`CHARM_TXT_OVERCHARMED`=护符过载、`CHARM_TXT_EQUIPPED`=已装备、`INV_NAME_NOTCH`=护符槽。
